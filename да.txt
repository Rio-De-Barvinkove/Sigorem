## КРИТИЧНА ПРОБЛЕМА:

### Матеріал `0` (повітря) НЕ ПРАЦЮЄ в Voxdot!

**ДОКАЗИ з логів:**

1. **Копання одного вокселя (радіус 0)**:
   ```
   VoxelInteractionHandler: Копання області радіусом 0
   DEBUG remove_voxel: world_pos=(2.55, 12.75, -2.35), half_size=0.05, voxel_scale=0.1
   ```

   Чи бачите ви зменшення кількості objects? **НІ!**

2. **Копання області (радіус 1) - 27 вокселів**:
   ```
   VoxelInteractionHandler: Копання області радіусом 1
   DEBUG remove_voxel: world_pos=(2.45, 12.65, -2.25)...
   (27 викликів)
   ```

   Після цього: `(PerformanceLogger) Active chunks: 14294.0`

   **Objects НЕ ЗМЕНШИЛИСЬ** після видалення 27 вокселів!

## ВИСНОВОК:

**Матеріал `0` в Voxdot НЕ ВИДАЛЯЄ вокселі, але і НЕ ГЕНЕРУЄ МЕШ!**

Коли ви "видаляєте" воксель з матеріалом `0`:
- Воксель стає "повітрям" (матеріал 0)
- Але **меш не перебудовується** для сусідніх вокселів
- **Немає нових граней** там, де повинна з'явитися порожнеча

## РІШЕННЯ:

### Варіант 1: Використовувати спеціальний матеріал для "порожнечі" (рекомендовано)

```gdscript
# У VoxdotController:
const AIR_MATERIAL = 255  # Спеціальний матеріал для порожнечі

func remove_voxel(world_pos: Vector3) -> void:
    if not terrain:
        return
    
    var half_size = voxel_scale * 0.5
    
    # Використовуємо спеціальний матеріал для "порожнечі"
    terrain.place_edit(
        Vector3(half_size, half_size, half_size),
        world_pos,
        AIR_MATERIAL,  # НЕ 0!
        1   # shape = cube
    )
    
    print("DEBUG remove_voxel: world_pos=%s, material=%s" % [world_pos, AIR_MATERIAL])
```

### Варіант 3: Патч для Voxdot (найкращий, але складний)

Потрібно змінити C++ код Voxdot, щоб:
1. Матеріал `0` генерував порожнечу
2. Сусідні вокселі отримували нові грані

## ШВИДКИЙ ТЕСТ:

func remove_voxel(world_pos: Vector3) -> void:

**Якщо після цього з'являться вокселі з матеріалом 255, то проблема в матеріалі 0.**
